# 데이터 모델과 API 설계 (실서비스 전환용)

지금은 화면 상태 `S` 전체를 `data/state.json` 하나에 저장해요.
실제 서비스에서는 아래처럼 테이블로 나누고, **모든 조회·수정 API가 로그인한 사람의 기관과 권한을 확인**해야 해요.

## 1. 지금 `S` 의 주요 키 → 앞으로의 테이블

| `S` 키 | 내용 | 테이블 (제안) |
|---|---|---|
| `orgs` | 기관 (사업자번호/고유번호, 회사 아이디 `code`, 유형, 회의비 한도) | `organizations` |
| `people` | 직원 (기관, 부서, 위계, 역할, 아이디, 계정 상태, 4대보험·퇴직 적용) | `users` |
| `orgCfg`·`levels`·`units`·`lineTpl`·`formLines`·`amtRules` | 조직도·위계·결재선 규칙 | `org_units`, `approval_line_rules` |
| `pay`, `ins` | 연도별 급여, 4대보험 요율 | `salaries(user_id, year, monthly)`, `insurance_rates(org_id, year, …)` |
| `stamps`, `orgSeal` | 개인 도장·서명, 기관 직인 | `user_stamps`, `org_seals` (이미지는 파일 저장소) |
| `projects` | 과제 (사업명, 부처, 기간, 관리팀, 단계 제안/추진/종료, 연구단 코드) | `projects` |
| `projects[].parts` | 참여기관 (구분 총괄/1세부, 역할, 상태 신청 중/초대 중/수락, 예산, 현물) | `project_orgs`, `budgets(project_org_id, year_no, item, cash, inkind)` |
| `projects[].years` | 연차 (기간, 마감, 예산·계획 스냅숏) | `project_years` |
| `projects[].mplan` | 월차별 추진 일정 | `project_month_plans` |
| `projects[].plan`, `subplan` | 월별 비목 계획표 | `monthly_plans` |
| `projects[].events` | 연구단 공동 일정 | `consortium_events` |
| `parts[].prop` | 연구제안 편성 (정부지원, 기관부담률, 현금비율, 인건비, 비목) | `proposal_budgets`, `proposal_staff` |
| `rates`, `rkind` | 과제별 참여율, 현금/현물 | `participations(user_id, project_id, year_no, rate, fund)` |
| `entries` | 집행 건 (비목·세부유형·금액·재원·참석자·증빙 O/X) | `expenses`, `expense_people`, `expense_evidence` |
| `made` | 플랫폼에서 작성한 증빙 서식 내용 | `evidence_documents` |
| `receipts` | 앱으로 올린 영수증 | `receipts` (사진은 파일 저장소) |
| `meetings` | 회의 (예비/완료, 참석자, 전문가) | `meetings`, `meeting_attendees` |
| `docs` | 제안서·보고서·회의록 (공개 범위 전체/소속, 읽어 낸 문단) | `documents`, `document_paragraphs` |
| `experts`, `expGroups` | 외부 전문가와 그룹 | `experts`, `expert_groups` |
| `appr` | 전자결재 문서 (결재선, 로그, 연결된 집행) | `approvals`, `approval_steps`, `approval_logs` |
| `AFORMS`, `TPL`, `CAT` | 결재 양식, 증빙 서식, 별표 7 기준 | `approval_forms`, `evidence_templates`, `evidence_rules` |
| `collect` | 보고서 취합 요청·제출 | `report_collections`, `report_submissions` |
| `projects[].invites` | 연구단 1회용 초대번호 (구분·역할·만료·사용 기관) | `consortium_invites` |
| `projects[].pyears` | 연구제안 차년도 기간 | `proposal_years` |
| `reports` | 주간 업무보고 (주, 프로젝트, 지난주 실적, 금주 계획, 구성원) | `weekly_reports` |
| `cevents` | 회사일정 (연차·반차·외출·출장·회의·교육·행사·기타) | `company_events` |
| `grades`, `pgrade` | 연도별 급여 등급표(과세·비과세)와 직원 등급 | `pay_grades`, `user_pay_grades` |
| `leaveAdj` | 연차 조정 | `leave_adjustments` |
| `appr[].rx` | 전자결재 ↔ 연구비 연동 (과제·비목·세부유형·금액) → 최종 승인 시 집행 생성 | `approvals.project_id`, `expenses.approval_id` |

`view`, `menu`, `tab`, `modal`, `f`, `teamF`, `openTabs` 같은 키는 **화면 상태**라 DB에 넣지 않아요.

## 2. 꼭 서버에서 지켜야 할 규칙

- **기관 분리**: 모든 테이블에 `org_id`를 두고, 조회할 때 로그인 사용자의 기관으로 거릅니다.
- **연구단 공유 범위**
  - 같은 연구단에 `수락` 상태로 참여한 기관끼리만 과제를 공유해요.
  - 다른 기관에는 기관별 예산·집행 **합계**만 보여 줘요. 집행 건별 내역, 증빙, 회의비는 보여 주지 않아요.
  - 제안 단계에서는 기관별 편성 **총액**을 공유해요.
- **참여 신청**: 연구단 코드로 신청하면 `신청 중` 상태가 돼요. 총괄기관 관리자가 승인한 뒤에만 과제를 조회할 수 있어요.
- **문서 공개 범위**: `share='소속'`인 문서는 올린 기관만 볼 수 있어요.
- **결재 권한**: 결재선의 현재 차례인 사람만 승인·반려할 수 있어요. 승인하면 그 사람의 도장이 찍혀요.
- **마감된 연차·종료된 과제**: 조회와 내려받기만 허용해요.
- **참여율 합계**: 수행 중 과제 참여율의 합이 100%를 넘지 않는지 서버에서도 확인해요.

## 3. API 설계 (예시)

```
POST   /api/auth/login                 회사 아이디 + 직원 아이디 + 비밀번호
POST   /api/orgs                       기관 가입 (사업자번호/고유번호)
GET    /api/users  POST /api/users     직원 계정 (관리자)
GET    /api/payroll/:year              급여·보험 요율   PUT 같은 경로로 수정

GET    /api/projects?phase=&team=      우리 기관이 참여한 과제
POST   /api/projects                   과제 등록 / 제안 과제 등록
POST   /api/projects/:id/join          연구단 코드로 참여 신청
POST   /api/projects/:id/orgs/:org/approve   참여 승인 (총괄기관)
PUT    /api/projects/:id/budget        우리 기관 예산 편성 (현금/현물)
POST   /api/projects/:id/years/close   연차 마감 → 다음 연차
POST   /api/projects/:id/convert       제안 → 추진 전환
GET    /api/projects/:id/summary       연구단 총괄 (기관별 합계만)

GET    /api/expenses?project=&item=    집행 (우리 기관만)
POST   /api/expenses                   집행 등록
PUT    /api/expenses/:id/evidence/:doc 증빙 작성·첨부
GET    /api/expenses/:id/pdf           A4 증빙 PDF
GET    /api/expenses/:id/zip           건별 ZIP

GET/POST /api/meetings                 회의
POST   /api/receipts                   앱 영수증 업로드 (사진 → AI 읽기)
GET/POST /api/documents                제안서·보고서

GET    /api/approvals?box=wait         전자결재 함
POST   /api/approvals                  기안
POST   /api/approvals/:id/approve      승인 (도장)
POST   /api/approvals/:id/reject       반려

POST   /api/ai/stream                  (지금 있음) 회의록·자문의견서 초안
POST   /api/ai/json                    (지금 있음) 영수증 읽기, 추진 일정 추출
```

## 4. 추천 기술 조합

- DB: PostgreSQL + Prisma (스키마를 코드로 관리하고 마이그레이션이 쉬워요)
- 인증: 세션 쿠키(httpOnly) 또는 JWT, 비밀번호는 bcrypt/argon2 해시
- 파일: S3 호환 저장소 (AWS S3, NCP Object Storage 등)
- PDF: 지금처럼 브라우저에서 만들어도 되고, 서버에서 만들려면 Playwright로 HTML을 PDF로 바꿔요
